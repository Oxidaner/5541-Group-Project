# 实验协议与来源

确认日期：2026-11-15。选题已由用户确认，成员分工留空。

## 原论文对应实验

[原论文 Table 5](https://arxiv.org/html/2010.11929v2#S6.T5)列出的 ImageNet-21k 预训练 ViT-B/32 在 CIFAR-10 上微调准确率为 **98.79%**。表中使用 384 分辨率。[附录 B.1.1](https://arxiv.org/html/2010.11929v2#A2.SS1.SSS1)规定 CIFAR-10 微调 10,000 步、batch size 512、SGD momentum 0.9、cosine 衰减、无 weight decay、全局梯度裁剪 1，并用训练集的 2% 进行开发集选参。

另外，[作者仓库](https://github.com/google-research/vision_transformer)报告 ViT-B/32 CIFAR-10 的复跑结果为 98.88% 和 98.75%。这些是参考值，不是本项目实测值。

## 实测结果

各次运行用验证集选择 checkpoint，再评估官方 10,000 张测试图像。训练过程中查看了多次验证分数，并据此挑选 checkpoint。测试结果只在每轮训练结束、checkpoint 固定后计算一次；其中 LR=0.000375 的 run 测试准确率用于决定另试 LR=0.003，因此 LR 比较属于探索性结果，不是独立确认实验。需要确认性比较时，应先冻结方案，再使用未查看过的测试 split。各 run 使用相同 seed 和分层训练/验证拆分。参考论文准确率为 98.79%。

线性探测表中的 5.16 秒只包括缓存特征上的选参和拟合；首次运行还需训练集特征提取约 134.86 秒、测试集特征提取约 37.11 秒。不能把 5.16 秒直接与微调端到端用时比较。

| 实验 | 可训练参数 | 实际预算 | 验证准确率 | 选中步数 | 测试准确率 | 比论文低 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 冻结特征 + logistic regression（扩展对照） | 7,690 | 5.16 秒拟合与搜索 | 97.50% | 不适用 | **96.13%** | 不直接与微调参考比较 |
| 只训练线性头（扩展对照） | 7,690 | 500 步，174 秒 | 96.70% | 400 | 94.70% | 不直接与论文 Table 5 比较 |
| 最后一个 block（扩展对照） | 7,097,098 | 300 步，88 秒 | 92.10% | 200 | 91.51% | 不直接与论文 Table 5 比较 |
| 最后一个 block，长程（扩展对照） | 7,097,098 | 3,000 步，664 秒 | 94.20% | 1,000 | 92.56% | 不直接与论文 Table 5 比较 |

最终 LR=0.003 的最佳验证 checkpoint 在 600 步，测试正确 9,757/10,000 张。每类测试正确数为 airplane 990/1,000、automobile 990/1,000、bird 969/1,000、cat 950/1,000、deer 975/1,000、dog 949/1,000、frog 987/1,000、horse 985/1,000、ship 986/1,000、truck 976/1,000。逐样本预测和混淆矩阵位于对应的结果文件及 `results/figures/`。

实测说明：LR 0.003 全量微调测试准确率 97.57%，高于 LR 0.000375 的 95.63%。两组使用相同 seed、batch size、分辨率和协议，仅学习率不同；这是单种子对照，不能证明普遍规律。最佳 checkpoint 为第 600 步。

## 2026-11-17 PatchDropout 效率扩展

主复现仍为 ViT；新增代码改动应用 Liu et al., [PatchDropout: Economizing Vision Transformers Using Patch Dropout](https://arxiv.org/abs/2208.07220), WACV 2023。该方法通过 timm 1.0.22 的公共 `patch_drop_rate` 参数启用，不声称原创。训练前方案保存在 `docs/efficiency_plan.md`。

位置编码加入之后，在每张训练图像的 49 个 patch 中随机保留 `floor(49 × 0.75)=36` 个，并始终保留 CLS，共 37 tokens；基线共 50。验证、测试使用全部 50 tokens。测试时同权重的基线/改动模型在 CPU 检查中输出逐项完全相同；训练入口 hook 验证了 50/37 的 token 数，设备反向梯度有限。

两组新跑的设置均为 224 分辨率、batch 64、LR 0.003、1,000 步、100 步 warmup、每 200 步验证，使用同一权重、零初始化头、拆分及 seed。配置审计确认仅 `name`、`patch_drop_rate`、`training_tokens` 不同。按各自验证最高分选 checkpoint，平分保留较早者；先完成两组训练并固定 checkpoint，再运行 `test`。

| 新实验 | 训练 tokens | 最佳验证 | 测试 | 选中步数 | 1,000 步训练耗时 | 最终测试耗时 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| efficiency_baseline_1000 | 50 | 97.90% | 97.57% | 600 | 747.27 秒 | 41.74 秒 |
| efficiency_patchdrop25_1000 | 37 | 97.90% | 97.47% | 800 | 630.01 秒 | 43.11 秒 |

完整训练耗时下降 15.69%，节省 117.26 秒，速度比为 1.186×；测试差为 -0.10 个百分点（少答对 10 张）。达到预设的训练时间下降至少 10%、验证分数下降不超过 0.3 个百分点的实用目标。两组共同答对 9,704 张，仅基线答对 53 张，仅改动答对 43 张，共同答错 200 张。新基线的所有记录损失、验证分数及全部测试预测与旧最佳基线完全相同。

训练时间在设备同步后开始/结束，包含训练循环、加载、验证、CPU checkpoint 保存与 loader 收尾；不含模型初始化、数据集构造和最终测试。使用此次新基线计算比例，不能直接用旧基线的 672.25 秒算收益。每个条件仅一次完整训练，主机负载与温度可能影响实际秒数。

辅助微基准用设备驻留合成 batch 64，三轮交替条件顺序，每轮每条件 5 步 warmup、15 步计时；每步计时前后同步 MPS。forward/backward/clip/SGD 中位数为 0.56609 秒（基线）与 0.44062 秒（改动），减少 22.16%；每条件共 45 个计时步。这个范围不包括加载、验证、保存，不能与完整训练时间混用。

参数量仍为 87,462,922，测试仍处理 50 tokens，未测峰值内存，也不声称推理更快。方法收益来自训练 token 减少；早期验证分数较低，后期追平，可能体现了信息减少与正则化之间的取舍，单 seed 不能确定普遍机制或显著性。测试集已在先前探索中查看，本次固定 dropout 条件仍不能让它重新变成独立确认测试集。

复现入口 `scripts/reproduce_efficiency.sh`；配置、训练摘要、逐步日志和逐样本预测保存在两个新 run 中。`scripts/analyze_efficiency.py` 校验配置可比性、验证选点、测试样本数/概率/准确率，并生成准确率-时间图和验证曲线。

## 必须披露的差异

224 分辨率、batch size 64 和 1,000 步均偏离原论文的 384 分辨率、batch size 512 和 10,000 步。LR 0.003 属于论文 CIFAR-10 开发集搜索候选，但本项目没有复现大 batch 和完整训练日程。微调保留验证集且未在选参后用全量训练集重训；图像缩放由 torchvision/PIL 执行，与作者 TensorFlow 输入管线略有差异。

冻结骨干线性分类器和部分微调是本项目对照及效率扩展，不能冒充原论文 Table 5 的全量微调结果。最佳全量微调为 224 分辨率、batch 64、1,000 步，测试准确率 97.57%，低于原论文 98.79% 参考值 1.22 个百分点。只运行一个随机种子时，不声称测得了训练随机性的均值和方差。原论文没有规定课程复现的“相近”容差，因此报告差距，不自行宣布满足某个评分档。

## 图表实验

对应原论文 Figure 7 的位置编码相似性分析：计算全部 49 个 patch 位置向量的 49 × 49 cosine-similarity 矩阵，并量化二维网格中曼哈顿邻近位置和远距离位置的相似度。原图使用 ViT-L/32，本项目使用同 patch size 的公开 ViT-B/32；这是对应分析的可视化复现，不是原图的逐像素复制。

注意力对照取最后一个 block 的 Q/K 投影，按 attention 定义重新计算 softmax，平均所有 head 的 CLS-to-patch 权重，比较同一图像预训练与全量微调后的 7 × 7 patch 网格。该图显示微调后 CLS 注意力仍集中于上方角落，没有形成清楚的猫体轮廓；尽管该样本预测正确，注意力图不支持“模型定位到了物体”的结论。注意力权重只是相关性可视化，不能单独作为因果解释或检测定位结果。

## 第三方默认值核对

在编写配置前检查了本机安装的精确版本：timm 1.0.22、torch 2.8.0、torchvision 0.23.0、scikit-learn 1.7.2。

- 模型的 `orig_in21k` 配置已指定 `num_classes=0`，创建骨干时不重复指定。
- timm 模型的 dropout 与 stochastic depth 默认为 0，不增加显式关闭选项。
- 本次核对 `VisionTransformer.patch_drop_rate` 默认 0；基线不覆盖。改动条件显式设 0.25。`PatchDropout` 默认保留一个 prefix token、无需维持抽样后顺序；位置向量随 token 一起抽取，不重复实现抽样或额外覆盖默认设置。
- SGD 的 weight decay 默认是 0，不重复指定；momentum 默认是 0，因此按论文显式设为 0.9。
- Resize 默认 bilinear，不重复指定；RandomResizedCrop 默认面积下限 0.08，作者使用 0.05，因此显式改为 0.05。RandomHorizontalFlip 默认概率 0.5，不重复指定。
- LogisticRegression 默认 lbfgs 和 L2 penalty，不重复指定；C 参与验证集搜索。max_iter 默认 100，提高至 400 是为了给拟合足够的收敛空间，并保留库发出的收敛警告。
- 原始权重和 CIFAR-10 从作者/数据集原始存储获取；脚本使用支持字节区间的并行分块下载，不修改用户网络设置。

固定依赖版本详见 `requirements-lock.txt`。`artifacts/pretrained/provenance.json` 记录权重来源和哈希；`results/environment.json` 记录实际设备与软件版本。新增参数只用于必要的对照实验和预算控制，没有增加对第三方默认行为的无效覆盖。
